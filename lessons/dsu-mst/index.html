第 1 课 / 共 5 课 动态连通性入门

动态连通性与“帮派老大”直觉

如果地图上有 10 万座城市，边修路边问“城市 A 和城市 B 通不通”，每次都跑 DFS/BFS 会慢到超时。并查集用区区一个数组，就能把查询和合并做到近乎常数时间。

1. 痛点：为什么不能每次都 DFS？

想象一个不断演化的社交网络（或公路网），系统会交替执行两种操作，共 105 次：

  • 合并（Union）：在 u 和 v 之间修一条路，使它们所在的集合连通。
  • 查询（Find）：询问 u 和 v 目前是否互通。

如果每次查询都用 DFS/BFS 遍历整张图，单次耗时 O(n + m)，105 次查询就会达到 1010 级运算，直接 TLE（超时）。我们并不关心“怎么走过去”，只关心“它们属不属于同一个连通块”。

2. 直觉模型：每个集合选一位“帮派老大”

我们可以把每个连通块想象成一个江湖帮派：帮派里只有一位最终的老大（代表元，Root）。每个人只需记住自己的“直接上级” fa[x] 是谁；而老大的上级就是他自己，即 fa[root] == root。

图 1-1：并查集在逻辑上是一片“有根树森林”，箭头由子节点指向父节点 fa[x]
两个核心操作的本质：
1. 查老大 find(x)：顺着 fa[x] 一路往上爬，直到遇到 fa[r] == r，返回老大 r。
2. 合帮派 unite(u, v)：先找到各自的老大 ru = find(u)、rv = find(v)；若老大不同，只需让其中一个老大拜另一个老大为大哥：fa[rv] = ru！

第 2 课 / 共 5 课 复杂度飙升与神级优化

从退化成链到近乎 O(1)：路径压缩与按秩合并

朴素并查集在最坏情况下会退化成一条长链，查询退化到 O(n)。加上短短两行代码优化后，10 亿个节点也只需最多 4 步！

1. 危机：当森林退化成一条“糖葫芦”

如果我们不加控制地依次执行 unite(1,2)、unite(2,3)、unite(3,4)……每次都把旧树挂到新节点下面，整棵树就会变成高度为 n 的单链：1 ← 2 ← 3 ← 4 ← 5 ← 6。此时调用一次 find(6) 就要连跳 5 次，时间复杂度退化为 O(n)。

2. 优化一：路径压缩（Path Compression）

既然我们每次 find(x) 已经辛苦地一路爬到了最顶层的老大 root，何不在“回溯”的路上顺手告诉沿途的每一个小弟：“别找你原来的中层领导了，以后直接认总老大当上级！”

int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); }

仅仅多写了一个 fa[x] =，一次查询就会把整条长链瞬间拍扁成深度为 1 的星形结构，后续所有查询一步直达老大！

3. 优化二：按秩合并（Union by Rank / Size）

合并两棵树时，如果把“大高个树”挂到“矮个子树”下面，整体高度会 +1；反过来，永远把矮树（秩小）挂到高树（秩大）下面，树高就几乎不会增长。单靠按秩合并，就能严格保证树高不超过 O(log n)。

4. 强强联手：神秘的阿克曼反函数 α(n) ≤ 4

同时使用路径压缩 + 按秩合并时，单次操作的均摊时间复杂度为 O(α(n))，其中 α(n) 是增长极其缓慢的阿克曼反函数（Inverse Ackermann Function）：

  • 当 n ≤ 1080（全宇宙可观测原子总数！）时，α(n) 依然 ≤ 4。
  • 因此在实际算法竞赛与工程中，优化后的并查集可以放心当作 O(1) 使用。

第 3 课 / 共 5 课 图论核心应用

最小生成树（MST）与 Kruskal 贪心算法

要在 n 座村庄之间铺设光纤，使任意两村互通且总造价最低，这就是经典的最小生成树问题。并查集正是 Kruskal 算法实现 O(1) 判环的灵魂引擎！

1. 什么是最小生成树（Minimum Spanning Tree）？

给定一张包含 n 个顶点、m 条带权无向边的连通图，我们要选出其中的一部分边构成一棵生成树：

  • 连通所有点：任意两个村庄都能互相到达。
  • 不含任何环：有环就一定存在多余的边，砍掉它更省钱！因此恰好选中 n − 1 条边。
  • 总权值最小：选出的 n − 1 条边权值之和达到全局最小。

2. Kruskal 算法：最直觉的“挑便宜货”贪心

Kruskal 算法的思路简单得令人拍案叫绝：先把所有边按价格从便宜到贵排好队，然后一条条试着买：

  1. 将所有 m 条边按权值 w 从小到大排序。
  2. 初始化并查集：每个点各自为一个独立帮派（共 n 个连通块）。
  3. 依次考察每一条边 (u, v, w)：
    • 用并查集查询 find(u) == find(v)：若相等，说明 u 和 v 早就连通了，再选这条边就会形成环 → 果断跳过（红色虚线）！
    • 若不等，说明这条边连接了两个尚未互通的区域 → 选中加入 MST（绿色实线），执行 unite(u, v)，累加权值 ans += w。
  4. 当选满 n − 1 条边 时立刻结束；若扫完所有边仍不足 n − 1 条，说明原图不连通，不存在最小生成树。
总时间复杂度 = 边排序 O(m log m) + 并查集判环 O(m · α(n)) = O(m log m)
为什么说并查集和 Kruskal 是天作之合？
每次考察一条边都要判断“加上它会不会成环”。如果用 DFS 判环，总复杂度会退化到 O(m · n)；而用并查集判断 find(u) == find(v)，每次只需近乎 O(1) 时间！

第 4 课 / 共 5 课 算法正确性证明

为什么 Kruskal 贪心一定正确？

贪心算法常常“看起来很美，其实有反例”。凭什么每次只顾眼前选最便宜的不成环边，最终一定能得到全局最优解？答案藏在两条优美的图论定理中。

1. 切分定理（Cut Property）—— 为什么“选它”绝不吃亏

把图中的所有顶点任意分成两个非空阵营 S 和 V \ S（称为一个切分）。所有一端在 S、另一端在 V \ S 的边称为横跨边。

切分定理：对于任意一个切分，权值最小的那条横跨边 e，一定属于某棵最小生成树！
图 4-1：反证替换法 —— 若某棵 MST 没选最轻横跨边 e=3，把 e 加进去会形成环，砍掉环上另一条横跨边 e'=9 后，总权值只降不升！

三句话证明（交换论证法）：

  1. 假设存在一棵最优树 T 居然没有选最轻横跨边 e。
  2. 把 e 强行加入 T，必然恰好形成一个环；既然 e 从 S 跨到了 V \ S，这个环想绕回来，就必然还包含另一条横跨边 e'。
  3. 因为 e 是最轻的横跨边，必有 w(e) ≤ w(e')。把 e' 踢掉换成 e，新树依然连通无环，且总价更低或相等！所以选 e 永远安全。

2. 环性质（Cycle Property）—— 为什么“跳过它”绝不后悔

当 Kruskal 考察一条边 e = (u, v) 时，如果发现 find(u) == find(v)：

  • 说明此前已经选出了一些边，把 u 和 v 连成了一条路径；
  • 因为我们是按边权从小到大排序考察的，那条路径上所有已选边的权值都 ≤ w(e)；
  • 因此 e 一定是这个环里最重（之一）的边！根据环性质，任意环上最重的边永远不需要出现在最小生成树里，直接丢弃毫无遗憾。

洛谷 P3367 【模板】并查集 普及-
题意：给定 N 个元素（N ≤ 2×105）和 M 次操作（M ≤ 106）。操作 1：合并 X, Y 所在集合；操作 2：查询 X, Y 是否在同一集合，输出 Y 或 N。
要点：同时加上路径压缩 + 按秩合并，并关闭流同步加速读入，即可稳过 106 次操作。
把样例搬进右侧演示台
一键在 DSU 演示台重放合并与连通性查询。
P3367_dsu.cpp · C++17 (AC) 
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 200005;
int fa[MAXN], rk[MAXN];

int find(int x) {
    return fa[x] == x ? x : fa[x] = find(fa[x]); // 路径压缩
}

void unite(int x, int y) {
    int rx = find(x), ry = find(y);
    if (rx == ry) return;
    if (rk[rx] < rk[ry]) swap(rx, ry); // 按秩合并：矮树挂高树
    fa[ry] = rx;
    if (rk[rx] == rk[ry]) rk[rx]++;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= n; i++) fa[i] = i, rk[i] = 0;

    while (m--) {
        int z, x, y;
        cin >> z >> x >> y;
        if (z == 1) unite(x, y);
        else cout << (find(x) == find(y) ? "Y\n" : "N\n");
    }
    return 0;
}
洛谷 P3366 【模板】最小生成树 普及/提高-
题意：给定 N 点 M 边无向图（N ≤ 5000, M ≤ 2×105），求最小生成树边权和；若图不连通输出 orz。
要点：边列表按权值升序排序 + 并查集判环；记录选中边数 cnt，最终若 cnt == n - 1 则输出总权值，否则输出 orz。
在右侧 MST 画布动态重放 Kruskal
观察排序、查根、选边累加权值与成环跳过的完整过程。
P3366_kruskal.cpp · C++17 (AC) 
#include <bits/stdc++.h>
using namespace std;

struct Edge {
    int u, v, w;
    bool operator<(const Edge& o) const { return w < o.w; }
};

int fa[5005];
int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); }

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    vector<Edge> edges(m);
    for (int i = 0; i < m; i++) cin >> edges[i].u >> edges[i].v >> edges[i].w;

    sort(edges.begin(), edges.end());
    for (int i = 1; i <= n; i++) fa[i] = i;

    long long ans = 0;
    int cnt = 0;
    for (const auto& e : edges) {
        int ru = find(e.u), rv = find(e.v);
        if (ru != rv) {
            fa[ru] = rv;
            ans += e.w;
            if (++cnt == n - 1) break;
        }
    }

    if (cnt == n - 1) cout << ans << "\n";
    else cout << "orz\n";
    return 0;
}
洛谷 P1525 [NOIP2010 提高组] 关押罪犯 普及+/提高
题意：有 N 名罪犯要分到 2 座监狱，有 M 对罪犯存在怨气值 c。如果一对有怨气的罪犯被关在同一监狱，就会发生影响力为 c 的冲突。请最小化“最大冲突影响力”。
核心建模（贪心 + 扩展域并查集）：
  • 贪心排序：先把所有怨气关系按 c 从大到小排序，优先把怨气最大的一对拆散到不同监狱！
  • 扩展域技巧：开 2N 个点 —— x 表示“x 的同类（同监狱）”，x + n 表示“x 的敌人（对立监狱）”。
  • 要拆散 u 和 v，就执行“敌人的敌人是朋友”：unite(u, v + n) 和 unite(v, u + n)。
  • 冲突终止：在处理某对 (u, v, c) 前，一旦发现 find(u) == find(v)，说明他俩已被迫在同一监狱，无法避免，当前的 c 就是答案！若全程无冲突则输出 0。
用 DSU 画布直观理解“敌人的敌人是朋友”
假设 1 和 2 敌对、2 和 3 敌对，则 1 和 3 必须在同一监狱（合并为同集），若此时 1 和 3 也有怨气就必然冲突！
P1525_prisoners.cpp · C++17 (AC) 
#include <bits/stdc++.h>
using namespace std;

struct Pair {
    int u, v, c;
    bool operator<(const Pair& o) const { return c > o.c; } // 按怨气从大到小
};

int fa[40005]; // 开 2*N 空间：1..n 为同类域，n+1..2n 为敌人域
int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); }
void unite(int x, int y) { fa[find(x)] = find(y); }

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;
    vector<Pair> a(m);
    for (int i = 0; i < m; i++) cin >> a[i].u >> a[i].v >> a[i].c;

    sort(a.begin(), a.end());
    for (int i = 1; i <= 2 * n; i++) fa[i] = i;

    for (const auto& p : a) {
        if (find(p.u) == find(p.v)) {
            cout << p.c << "\n"; // 无法拆散，当前怨气值即最小最大冲突
            return 0;
        }
        unite(p.u, p.v + n); // u 与 v 的敌人同监狱
        unite(p.v, p.u + n); // v 与 u 的敌人同监狱
    }
    cout << 0 << "\n"; // 全程无冲突
    return 0;
}
