第 1 课 · 动机与直觉 约 3 分钟

贪心为何失效？为什么必须用动态规划？

面对容量有限的背包，人的第一直觉往往是“优先装性价比最高的物品”。但在物品不可切割（0-1 背包）时，贪心会直接掉进局部最优的陷阱。

1. 一个经典反例：性价比最高反而不划算！

假设背包总容量 W = 10，面前有 3 件物品（每件要么整件拿走，要么不拿）：

  • 物品 1：重量 w1 = 6，价值 v1 = 60（性价比 60 / 6 = 10.0）
  • 物品 2：重量 w2 = 5，价值 v2 = 45（性价比 45 / 5 = 9.0）
  • 物品 3：重量 w3 = 5，价值 v3 = 45（性价比 45 / 5 = 9.0）

如果按性价比从高到低贪心，先拿走物品 1 后，背包只剩 4 的空位——物品 2 和 3 都装不下了，白白浪费了 4 单位容量！而动态规划会放弃物品 1，拿走物品 2 + 物品 3，总价值高达 90。

图 1-1：当物品不可拆分时，“性价比最高”的物品可能留下无法利用的碎片空间
什么时候贪心才对？ 只有分数背包（物品像金沙一样可以切开拿一半）时，按性价比贪心才一定最优。一旦物品是离散的、不可分割的，就必须用动态规划（DP）系统地记录每个容量下的最优组合。

第 2 课 · 二维状态转移 约 4 分钟

0-1 背包二维 DP：把大问题拆成“选或不选”

暴力枚举 n 件物品需要 2n 次尝试；动态规划通过定义二维状态表，把指数级搜索压缩成 O(nW) 的填表过程。

1. 状态定义：dp[i][j] 代表什么？

我们建一张 (n + 1) 行、(W + 1) 列的表格：

状态定义：dp[i][j] = 只考虑前 i 件物品，在背包容量不超过 j 的前提下，能够获得的最大总价值。

显然，第 0 行（没有物品可选）全是 0，即 dp[0][j] = 0；最终答案就是右下角 dp[n][W]。

2. 核心转移方程：面对第 i 件物品只有两个选择

计算 dp[i][j] 时，前 i − 1 行已经全部算好。针对第 i 件物品（重量 wi，价值 vi）：

  • 决策一：不选第 i 件 → 容量还是 j，问题退化成前 i − 1 件物品的最优解，直接抄正上方格子：dp[i-1][j]。
  • 决策二：选第 i 件（前提 j ≥ wi）→ 先给它腾出 wi 的空间，剩下 j − wi 的容量交给前 i − 1 件物品，再加上它的价值：dp[i-1][j - w[i]] + v[i]。
dp[i][j] = max( dp[i-1][j] , dp[i-1][j - w[i]] + v[i] )   (当 j ≥ w[i])
图 2-1：0-1 背包的每个格子只依赖上一行的“正上方”与“左上方”两个格子

3. 如何反推出“到底选了哪几件物品”？

填完表后，从右下角 (n, W) 往回走：若 dp[i][j] == dp[i-1][j]，说明第 i 件没选，直接往上走 (i-1, j)；否则说明选了第 i 件，记录它并跳往左上方 (i-1, j - w[i])！

第 3 课 · 空间优化核心 约 4 分钟

一维滚动数组：为什么内层循环必须“倒序”？

刚才我们发现第 i 行只依赖第 i − 1 行，更早的行再也用不到了。于是可以把二维数组压缩成长度仅为 W + 1 的一维数组 dp[0..W]！

1. 压缩成一维后的核心矛盾

当我们把 dp[i][j] 和 dp[i-1][j] 合并到同一个数组 dp[j] 里后，转移方程写成：

dp[j] = max( dp[j] , dp[j - w[i]] + v[i] )

仔细看等号右边的 dp[j - w[i]]：我们需要的是上一轮（第 i − 1 行）还没放第 i 件物品时的旧值！

2. 倒序（从 W 到 wi）vs 正序（从 wi 到 W）

  • ✅ 倒序遍历 for (int j = W; j >= w[i]; j--)：先更新右边的大容量 dp[j]，此时左边更小的下标 j - w[i] 还没有被本轮改写，存的依然是上一行的旧值！保证第 i 件物品最多只会被放进去 1 次。
  • ❌ 误写成正序 for (int j = w[i]; j <= W; j++)：先更新了左边较小的 dp[j - w[i]]（可能已经装进 1 件物品 i），后面算到更大的 dp[j] 时，又拿它再加一次 v[i]——结果同一件物品被装了 2 次、3 次……无意间写成了完全背包！
图 3-1：倒序遍历让“已更新的新值”始终留在当前指针右侧，左侧永远是干净的上一行旧值
空间复杂度骤降：从 O(nW) 降为 O(W)。当 n = 1000、W = 104 时，内存直接减少 1000 倍，只需几十 KB！

第 4 课 · 背包家族进阶 约 4 分钟

完全背包正序一行切换，与多重背包二进制拆分

刚才那个“正序遍历的 Bug”，换个视角竟然就是完全背包（每种物品无限件）的最优解！只改一行循环方向，算法立刻切换形态。

1. 完全背包：为什么正序恰好等价于“无限件”？

当每种物品可以拿任意多件时，二维状态转移方程只需把“选”的来源从上一行 i-1 改成当前行 i：

dp[i][j] = max( dp[i-1][j] , dp[i][j - w[i]] + v[i] )

因为 dp[i][j - w[i]] 里可能已经选了 0 件、1 件、2 件……第 i 种物品，再加上 1 件 vi，就自然覆盖了选 k 件（k ≥ 1）的所有情况！压成一维后，正序遍历 for (int j = w[i]; j <= W; j++) 恰好让 dp[j - w[i]] 取到本行刚更新的新值。

背包类型物品数量二维“选”来源一维内层循环方向时间 / 空间
0-1 背包 每种 1 件 dp[i-1][j - w[i]]（左上方） ← 倒序 W .. w[i] O(nW) / O(W)
完全背包 每种无限件 dp[i][j - w[i]]（同行左侧） → 正序 w[i] .. W O(nW) / O(W)
多重背包 每种 si 件 二进制拆分成 0-1 物品 ← 倒序（拆分后跑 0-1） O(nW log s) / O(W)

2. 多重背包的巧妙优化：二进制拆分

如果第 i 种物品最多只能选 si 件（例如 s = 13 件），直接拆成 13 个相同物品太慢了。我们可以按 2 的幂次打包：

  • 把 13 件拆成 4 个大礼包：1 件、2 件、4 件、以及剩下的 6 件（1 + 2 + 4 + 6 = 13）。
  • 神奇性质：从 {1, 2, 4, 6} 中任选若干个礼包，可以精准拼出 0 到 13 之间的任意整数件数！
  • 这样只需把 4 个打包后的新物品（重量 k·w，价值 k·v）丢进 0-1 背包里跑一遍即可，物品数量从 s 锐减到 log2 s！

第 5 课 · 工程与建模 约 3 分钟

走出题海：背包 DP 在真实世界中的 4 大应用

凡是“资源有上限（预算、内存、载重、时间），任务有收益，求最优组合或能否恰好凑出目标值”的问题，本质上都是背包模型。

1. 云计算虚拟机装箱 0-1 背包

云厂商的一台物理宿主机有固定 CPU / 内存配额，需要在大量待调度容器/VM 请求中选出一批部署，最大化机器利用率或计费收益。

建模：宿主机剩余内存 → 容量 W；每个 VM 内存需求 → wi；租户出价/优先级 → vi。

2. 投资组合与预算分配 0-1 / 完全

企业手握固定研发或营销预算，面对若干不可拆分的项目（如投广告渠道、采购设备），希望在预算红线内获得最大预期 ROI。

建模：总预算 → 容量 W；项目投入成本 → wi；预期净利润 → vi。

3. 物流货车与集装箱配载 0-1 / 多重

干线货车或海运集装箱有严格限重与容积上限，面对不同重量、运费单价的货物，合理配载能显著减少空驶损耗并提升单趟利润。

建模：货车核载重量 → 容量 W；货物重量 → wi；单件运费收益 → vi。

4. 负载均衡与密码学子集和 可行性背包

双核处理器分配一批不可拆分任务时，如何让两核耗时尽量接近？密码学中的 Merkle-Hellman 背包公钥体制也基于子集和问题。

建模：令背包容量 W = ⌊Sum / 2⌋，每个任务 wi = vi = 耗时，求最接近半数的子集和！
万能建模三步法：① 找出题目中的硬性上限作为背包容量 W；② 找出每个决策的消耗 wi 与收益 vi；③ 确认每种物品能选几次（1 次用 0-1 倒序，无限次用完全正序，有限次用二进制拆分）。

梯度实战题解：从模板题到变形建模

精选 3 道必刷经典题，覆盖 0-1 模板、完全背包（含防溢出细节）以及 LeetCode 高频变形题。均可直接提交 AC，并支持一键把样例加载到右侧演示！

题意：山洞里有 M 株不同的草药，采摘第 i 株需要时间 wi、价值 vi，每株只能采一次。给定总时间 T（T ≤ 1000, M ≤ 100），求最大总价值。

思路：最标准的 0-1 背包。总时间 T 即背包容量 W，内层时间循环倒序 for (int j = T; j >= w; j--) 即可 AC。

Luogu_P1048_01Knapsack.cpp（时间 O(MT)，空间 O(T)） 
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T, M;
    cin >> T >> M;
    vector<int> dp(T + 1, 0);

    for (int i = 0; i < M; i++) {
        int w, v;
        cin >> w >> v;
        // 0-1 背包：必须倒序遍历容量，防止同一株草药被采两次
        for (int j = T; j >= w; j--) {
            dp[j] = max(dp[j], dp[j - w] + v);
        }
    }
    cout << dp[T] << '\n';
    return 0;
}

题意：与 P1048 几乎完全相同，但每种草药可以无限制地疯狂采摘！且数据范围升级：T ≤ 107，M ≤ 104，保证 M × T ≤ 107。

思路与避坑：① 只需把内层循环改为正序 for (int j = w; j <= T; j++)；② 极大坑点：答案可能超过 32 位 int 上限（2.1 × 109），dp 数组必须开 long long！

Luogu_P1616_Unbounded.cpp（注意 long long） 
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T, M;
    cin >> T >> M;
    // 注意：总价值最高可达 1e11，必须使用 long long！
    vector<long long> dp(T + 1, 0);

    for (int i = 0; i < M; i++) {
        int w;
        long long v;
        cin >> w >> v;
        // 完全背包：正序遍历容量，允许同一种草药重复采摘
        for (int j = w; j <= T; j++) {
            dp[j] = max(dp[j], dp[j - w] + v);
        }
    }
    cout << dp[T] << '\n';
    return 0;
}

题意：给定一个只包含正整数的非空数组 nums，判断是否可以将这个数组分割成两个子集，使得两个子集的元素和相等。

思路：若总和 S 为奇数，直接返回 false；否则问题等价于：能否从数组中选出若干数，使其和恰好等于 target = S / 2？这就是布尔可行性 0-1 背包：dp[j] = dp[j] || dp[j - x]（在右侧演示台中，等价于设 w = v = x，检查 dp[target] == target）。

LeetCode_416_PartitionEqualSubsetSum.cpp（O(n · target)） 
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int sum = 0;
        for (int x : nums) sum += x;
        if (sum % 2 != 0) return false;

        int target = sum / 2;
        // dp[j] 表示能否凑出总和 j
        vector<char> dp(target + 1, 0);
        dp[0] = 1;

        for (int x : nums) {
            // 每个数只能用一次，倒序更新
            for (int j = target; j >= x; j--) {
                if (dp[j - x]) dp[j] = 1;
            }
        }
        return dp[target] == 1;
    }
};
