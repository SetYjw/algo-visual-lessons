为什么需要线段树？

当数组既要频繁“查询一段区间的和/最值”，又要频繁“修改某个点或一整段区间”时，传统方法都会卡死——线段树用“分治区间”把两者都压到对数级。

1. 老办法为什么不够用？

假设给你一个长度为 n = 105 的数组，接下来有 105 次操作，混合出现下面两种请求：

  • 区间查询：求 a[L] + a[L+1] + … + a[R]（或区间最大值、最小值）。
  • 单点 / 区间修改：把 a[x] 改成新值，或者把 a[L..R] 全部加上 v。
数据结构 单点修改 区间修改 区间查询 适用局限
直接暴力数组 O(1) O(n) O(n) 查询或区间改太慢，105 次直接超时
前缀和数组 O(n) O(n) O(1) 只适合静态数组，一修改就得重算
树状数组（BIT） O(log n) O(log n)* O(log n) 代码短但仅擅长可逆运算（如求和），难维护区间最值/乘加混合
线段树（Segment Tree） O(log n) O(log n) O(log n) 通用区间神器：求和、最值、乘加混合、区间赋值通吃

2. 核心直觉：像公司层级一样“分治管辖区间”

与其把所有数字平铺成一条长队，不如把整段区间 [1, n] 反复一分为二，直到拆成只含 1 个元素的叶子节点：

  • 根节点管辖总区间 [1, 6]，记下全员总和 24；
  • 左子树管辖前半段 [1, 3]（总和 8），右子树管辖后半段 [4, 6]（总和 16）；
  • 每个非叶子节点存的都是它所管辖区间的汇总信息（比如区间和 = 左孩子和 + 右孩子和）。
任何一段连续区间 [L, R]，都可以拆成极少数（不超过 2 log2 n 个）树节点的拼图！

第 2 课 / 共 5 课 树形存储与剪枝查询

建树（Build）与区间求和（Query）

线段树不需要写指针和结构体链表！它像堆一样直接存在一个普通数组里，用简单下标公式就能找到左右孩子。

1. 完全二叉树编号与 4n 空间

给根节点编号为 u = 1，对于任意节点 u（管辖区间 [l, r]，中点 mid = (l + r) >> 1）：

左孩子编号 = 2u（即 u << 1），管辖 [l, mid]
右孩子编号 = 2u + 1（即 u << 1 | 1），管辖 [mid + 1, r]
新手高频坑：数组到底开多大？
虽然有效节点只有 2n − 1 个，但因为最后一层叶子在数组下标中可能出现空洞，最坏情况（如 n = 2k + 1）最大下标会接近 4n。所以比赛与工程里一律开 4 * N，绝不越界！

2. 建树（Build）：先递下去，再汇总上来

  1. 如果 l == r，说明到了叶子节点，直接赋值 sum[u] = a[l] 返回。
  2. 否则分别递归建左子树 build(2u, l, mid) 和右子树 build(2u+1, mid+1, r)。
  3. 回溯时执行 pushUp(u)：sum[u] = sum[2u] + sum[2u+1]。

整棵树只有不到 2n 个有效节点，每个节点只建一次，因此建树总复杂度为 O(n)。

3. 区间求和（Query）：完全覆盖就直接返回！

查询目标区间 [L, R] 时，站在当前节点 [l, r] 只做三种判断：

① 完全覆盖 直接返回

如果 L ≤ l && r ≤ R，说明整个节点都在查询范围内，直接返回 sum[u]，绝不继续往下走！

② 部分重叠 分头递归

若 L ≤ mid 查左孩子，若 R > mid 查右孩子，最后把两边结果相加。

可以证明：在树的每一层，最多只会有 2 个节点出现“部分重叠”而继续分叉，因此整次查询访问的节点数不超过 4 log2 n，时间复杂度稳稳 O(log n)！

单点修改与向上汇总（pushUp）

当原数组中某一个位置 a[idx] 发生改变时，哪些树节点会受影响？答案是：只有从根到该叶子的那一条独木桥！

1. 顺藤摸瓜找叶子，原路返回更新祖先

假设我们要把 a[idx] 修改为新值 val：

  1. 向下定位：从根节点出发，比较 idx 与 mid：
    • 若 idx ≤ mid，往左孩子走；
    • 否则往右孩子走。
  2. 修改叶子：当到达 l == r == idx 时，直接把叶子更新为 sum[u] = val。
  3. 向上汇总（pushUp）：递归返回时，沿途每一个祖先节点都重新执行 sum[u] = sum[2u] + sum[2u+1]。
为什么把 pushUp(u) 单独抽成一个函数？
因为线段树的“骨架”是通用的，只有 pushUp 决定它维护什么信息！
  • 维护区间和：sum[u] = sum[2u] + sum[2u+1]
  • 维护区间最大值：mx[u] = max(mx[2u], mx[2u+1])
  • 维护区间最大公约数：g[u] = gcd(g[2u], g[2u+1])
只要运算满足结合律，换一行 pushUp 就能把线段树改造成全新武器！

第 4 课 / 共 5 课 · 核心重难点 懒惰传播

区间修改与懒标记（Lazy Tag & pushDown）

如果要把区间 [1, 100000] 的每个数都加 5，逐个改叶子会退化成 O(n)。懒标记的精髓只有八个字：先欠着账，用到再发！

1. 通俗类比：班主任的“欠条账本”

想象你是校长（根节点），要给三年级全体同学（区间 [1, 4]）每人发 +3 朵小红花：

  • 笨办法：亲自跑到每个学生桌前发花——累死（O(n)）。
  • 懒标记办法：直接找到管辖 [1, 4] 的年级主任：
    1. 立刻把年级总花数加上 3 × 4 = 12（sum[u] += val × len）；
    2. 在年级主任头上贴一张橙色欠条：lazy[u] += 3（意思是“你的手下每人还欠 3 朵花，先记着，别急着发”）；
    3. 立刻收工返回！完全不往下递归！
  • 什么时候兑现欠条（pushDown）？
    直到未来某次查询或修改必须进入他的左/右孩子（例如查询 [2, 3]），年级主任才赶在放行前，把自己的欠条 lazy[u] 下发给左右班主任，更新两个孩子的 sum 和 lazy，然后撕掉自己的欠条（lazy[u] = 0）！

2. pushDown(u, l, r) 的三步标准动作

当节点 u 的 lazy[u] != 0 且需要向下访问左右孩子时，执行：

1. 更新左孩子 (长度 mid - l + 1)：sum[2u] += lazy[u] × (mid - l + 1); lazy[2u] += lazy[u];
2. 更新右孩子 (长度 r - mid)：    sum[2u+1] += lazy[u] × (r - mid);   lazy[2u+1] += lazy[u];
3. 清空当前节点欠条：              lazy[u] = 0;
牢记黄金法则（防错必背）：
1. 只要准备往下递归左右孩子（无论是 query 还是 rangeAdd 还是 pointUpdate），必须先 pushDown，保证孩子拿到的是最新账目！
2. 节点的 sum[u] 永远是已经加上自身 lazy[u] 之后的真实区间和，而 lazy[u] 只代表“欠给子孙、尚未下传的增量”。

实战题解：洛谷 P3372 & P3373

吃透这两道经典模板题，线段树的单懒标记与多懒标记（先乘后加）就彻底通关了。所有代码均已开好 long long 与 4N 空间，可直接提交。

洛谷 P3372 【模板】线段树 1 普及+/提高

题意：给定长度为 n（≤ 105）的数列，支持 m（≤ 105）次操作：

  • 操作 1：1 x y k —— 将区间 [x, y] 内每个数加上 k。
  • 操作 2：2 x y —— 输出区间 [x, y] 内所有数的和。
解题要点：就是前 4 课讲的完整标准模板！注意题目数值累加可能超过 32 位整数，所有 sum、lazy、输入与返回值务必统一使用 long long。
一键加载 P3372 样例到演示台
原题样例数组 [1, 5, 4, 2, 3]，先执行区间 [2, 4] + 2，再查询 [1, 4]（答案应为 18）。
P3372_segment_tree_1.cpp（C++17 · 可直接 AC） 
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

const int MAXN = 100005;
ll a[MAXN], sum[MAXN << 2], lazy[MAXN << 2];

void pushUp(int u) {
    sum[u] = sum[u << 1] + sum[u << 1 | 1];
}

void applyTag(int u, int l, int r, ll val) {
    sum[u] += val * (r - l + 1);
    lazy[u] += val;
}

void pushDown(int u, int l, int r) {
    if (lazy[u] == 0) return;
    int mid = (l + r) >> 1;
    applyTag(u << 1, l, mid, lazy[u]);
    applyTag(u << 1 | 1, mid + 1, r, lazy[u]);
    lazy[u] = 0;
}

void build(int u, int l, int r) {
    lazy[u] = 0;
    if (l == r) { sum[u] = a[l]; return; }
    int mid = (l + r) >> 1;
    build(u << 1, l, mid);
    build(u << 1 | 1, mid + 1, r);
    pushUp(u);
}

void rangeAdd(int u, int l, int r, int L, int R, ll val) {
    if (L <= l && r <= R) {
        applyTag(u, l, r, val);
        return;
    }
    pushDown(u, l, r);
    int mid = (l + r) >> 1;
    if (L <= mid) rangeAdd(u << 1, l, mid, L, R, val);
    if (R > mid)  rangeAdd(u << 1 | 1, mid + 1, r, L, R, val);
    pushUp(u);
}

ll query(int u, int l, int r, int L, int R) {
    if (L <= l && r <= R) return sum[u];
    pushDown(u, l, r);
    int mid = (l + r) >> 1;
    ll res = 0;
    if (L <= mid) res += query(u << 1, l, mid, L, R);
    if (R > mid)  res += query(u << 1 | 1, mid + 1, r, L, R);
    return res;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= n; ++i) cin >> a[i];
    build(1, 1, n);
    while (m--) {
        int op, x, y;
        cin >> op >> x >> y;
        if (op == 1) {
            ll k; cin >> k;
            rangeAdd(1, 1, n, x, y, k);
        } else {
            cout << query(1, 1, n, x, y) << '\n';
        }
    }
    return 0;
}

洛谷 P3373 【模板】线段树 2 提高+/省选-

题意：同时支持三种操作（结果对 mod 取模）：

  • 操作 1：区间 [x, y] 每个数乘上 k；
  • 操作 2：区间 [x, y] 每个数加上 k；
  • 操作 3：查询区间 [x, y] 的和模 mod。

核心难点：为什么必须“先乘后加”？

给每个节点维护两个懒标记：mul（初始为 1）和 add（初始为 0），约定它们合起来代表一次仿射变换：

新值 = 原值 × mul + add

现在看新来的修改如何合并到已有的 (mul, add) 上：

  • 新来一个区间加 +d：(x × mul + add) + d = x × mul + (add + d) → 只改 add += d。
  • 新来一个区间乘 ×k：(x × mul + add) × k = x × (mul × k) + (add × k) → 加法标记也要跟着乘 k！
如果反过来“先加后乘”会怎样？
如果约定 (x + add) × mul，那么新来一个 +d 时会变成 (x + add + d / mul) × mul，出现除法和精度/逆元问题！所以“先乘后加”是唯一优雅的无除法方案。
P3373_segment_tree_2.cpp（C++17 · 先乘后加 · 可直接 AC） 
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

const int MAXN = 100005;
ll a[MAXN], sum[MAXN << 2], mul[MAXN << 2], addTag[MAXN << 2];
ll MOD;

void pushUp(int u) {
    sum[u] = (sum[u << 1] + sum[u << 1 | 1]) % MOD;
}

// 对节点 u 施加变换：x -> x * m + d（先乘后加）
void applyTag(int u, int l, int r, ll m, ll d) {
    sum[u] = (sum[u] * m + d * (r - l + 1)) % MOD;
    mul[u] = (mul[u] * m) % MOD;
    addTag[u] = (addTag[u] * m + d) % MOD;
}

void pushDown(int u, int l, int r) {
    if (mul[u] == 1 && addTag[u] == 0) return;
    int mid = (l + r) >> 1;
    applyTag(u << 1, l, mid, mul[u], addTag[u]);
    applyTag(u << 1 | 1, mid + 1, r, mul[u], addTag[u]);
    mul[u] = 1;
    addTag[u] = 0;
}

void build(int u, int l, int r) {
    mul[u] = 1;
    addTag[u] = 0;
    if (l == r) { sum[u] = a[l] % MOD; return; }
    int mid = (l + r) >> 1;
    build(u << 1, l, mid);
    build(u << 1 | 1, mid + 1, r);
    pushUp(u);
}

void update(int u, int l, int r, int L, int R, ll m, ll d) {
    if (L <= l && r <= R) {
        applyTag(u, l, r, m, d);
        return;
    }
    pushDown(u, l, r);
    int mid = (l + r) >> 1;
    if (L <= mid) update(u << 1, l, mid, L, R, m, d);
    if (R > mid)  update(u << 1 | 1, mid + 1, r, L, R, m, d);
    pushUp(u);
}

ll query(int u, int l, int r, int L, int R) {
    if (L <= l && r <= R) return sum[u];
    pushDown(u, l, r);
    int mid = (l + r) >> 1;
    ll res = 0;
    if (L <= mid) res = (res + query(u << 1, l, mid, L, R)) % MOD;
    if (R > mid)  res = (res + query(u << 1 | 1, mid + 1, r, L, R)) % MOD;
    return res;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q >> MOD;
    for (int i = 1; i <= n; ++i) cin >> a[i];
    build(1, 1, n);
    while (q--) {
        int op, x, y;
        cin >> op >> x >> y;
        if (op == 1) {
            ll k; cin >> k;
            update(1, 1, n, x, y, k % MOD, 0);
        } else if (op == 2) {
            ll k; cin >> k;
            update(1, 1, n, x, y, 1, k % MOD);
        } else {
            cout << query(1, 1, n, x, y) << '\n';
        }
    }
    return 0;
}
