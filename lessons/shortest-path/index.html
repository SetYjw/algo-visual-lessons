最短路问题与核心武器——“松弛（Relaxation）”

导航软件如何在几毫秒内算出你到城市每个角落的最短车程？几乎所有单源最短路算法，底层都只反复做一件事：松弛。

1. 什么是单源最短路（SSSP）？

给定一张带权有向图（节点表示路口，有向边 u → v 及边权 w 表示单行道耗时）和一个起点 S，我们需要求出 S 到图中每一个节点 v 的最小总耗时，记作 dist[v]。

一开始我们什么路都没走过，所以把距离初始化为：

  • dist[S] = 0（起点到自己距离为 0）；
  • 其余所有节点 dist[v] = ∞（表示暂时不可达，代码中常设为 1e18 或 0x3f3f3f3f）。

2. 核心武器：松弛（Relaxation）与三角形不等式

假设目前已知从起点到 u 需要 dist[u] 分钟，到 v 需要 dist[v] 分钟。现在发现一条有向边 u → v，耗时 w。如果“先走到 u，再走这条边到 v”比原先的方案更短，我们就立刻更新 dist[v]：

if (dist[u] + w < dist[v])   dist[v] = dist[u] + w;
绕道 u 后耗时 2 + 3 = 5 < 6，就像把一根绷紧的橡皮筋放“松弛”了，直到所有边都满足三角形不等式 dist[v] ≤ dist[u] + w。
为什么叫“松弛（Relaxation）”？
早期数学规划中，把 dist[v] 看作从 S 到 v 的距离上界估计。发现更短路径时，这个估计值向下收紧，原本紧绷的误差约束被“松弛”了。当图中没有任何一条边还能松弛时，所有 dist[v] 就是精确的最短路！

第 2 课 / 共 5 课 贪心锁点 · 优先队列优化

Dijkstra 的贪心直觉与优先队列优化

如果随便乱选边来松弛，可能同一个节点会被反复更新很多次。Dijkstra 用一个极聪明的贪心策略：每次只挑当前 dist 最小的未锁定节点，直接永久锁定！

1. 为什么弹出最小 dist 就能“永久锁定”？

前提是所有边权非负（w ≥ 0）。假设在所有尚未锁定的节点中，u 的 dist[u] 是最小的：

  • 能不能先绕去别的未锁定节点 x，再绕回 u 得到更短距离？
  • 不可能！因为 x 还没锁定，一定有 dist[x] ≥ dist[u]；而且后续所有边权都 ≥ 0，越走只会越长或相等，绝对不可能比 dist[u] 更小！

因此，一旦 u 成为未锁定集合中的最小值，它的 dist[u] 就已经盖棺定论（图中染成绿色），以后再也不用修改它。

2. 从 O(n2) 到 O((n + m) log n)：小根堆优化

朴素 Dijkstra 每次都要扫描全部 n 个点找最小值，总复杂度 O(n2)，在 n = 105 时必定超时。我们可以用 C++ 的小根堆 priority_queue 维护待选的 (dist, u) 二元组：

  • 每次松弛成功 dist[v] = dist[u] + w 时，直接把新的 (dist[v], v) 压入堆中；
  • 每次从堆顶弹出当前最小的 (d, u)，只需 O(log n)。

3. 最容易写错的一行：if (d > dist[u]) continue;

为什么要跳过过期状态？
C++ 标准库的 priority_queue 不支持修改堆内已有元素的值。所以当节点 3 先被更新为 6（入队 (6, 3)），后来又被松弛成 5（再入队 (5, 3)）时，堆里会同时存在新旧两个版本！
较小的 (5, 3) 会先出队并把节点 3 锁定；等后面旧的 (6, 3) 出队时，我们检查 d > dist[u]（6 > 5），立刻 continue 丢弃它，避免重复扫边导致超时！

Dijkstra 的死穴——为什么负权边会让它翻车？

刚才证明“永久锁定”时，我们依赖了一个前提：所有边权 ≥ 0。只要图里混进哪怕一条负权边，这个贪心假设就会瞬间崩塌！

1. 只需 4 个节点，就能让 Dijkstra 算错

看下面这张极简的 4 节点有向图，起点为 S = 1，其中有一条负权边 2 → 3 (w = -6)：

真实最短路：1 → 2 → 3 总长 5 + (-6) = -1，再到 4 总长 0；但 Dijkstra 会算出 dist[3] = 2，dist[4] = 3！

2. 复盘“翻车”全过程

  1. 从起点 1 出发，松弛得到 dist[2] = 5，dist[3] = 2。
  2. 优先队列弹出最小值 (2, 3)，Dijkstra 自信地把节点 3 永久锁定为 2，接着推出 dist[4] = 3 并锁定 4。
  3. 最后弹出 (5, 2)，扫描到负权边 2 → 3 (-6)，算出更短距离 5 + (-6) = -1 < 2！
  4. 但此时节点 3 已经被锁定，一切都晚了——错误沿着 3 → 4 继续传播，节点 3 和 4 全都算错！
那如果干脆不写 vis[u]，允许已锁定节点反复重新入队呢？
确实可能修正部分负权边，但它就不再是 Dijkstra 了：一旦遇到特定构造的负权图，重复入队次数会暴涨到指数级 O(2n)；如果图里还有负环，甚至会直接死循环 TLE！

第 4 课 / 共 5 课 全局松弛 · 负环检测

Bellman-Ford 与 SPFA：处理负权边与检测负环

既然负权图不能“永久锁定”任何节点，那就彻底放弃贪心，改为多轮反复松弛——这就是 Bellman-Ford 和它的队列优化版 SPFA。

1. Bellman-Ford：简单粗暴但绝对可靠

核心思想：进行 n − 1 轮迭代，每一轮都遍历图中的所有 m 条边，尝试执行松弛 dist[v] = min(dist[v], dist[u] + w)。

  • 为什么恰好是 n − 1 轮？ 如果没有负环，任何两点间的最短路一定不会重复经过同一个点，因此最多包含 n − 1 条边。第 k 轮结束后，所有“最多经过 k 条边”的最短路都已找到！
  • 提前结束优化：如果某一整轮扫描下来，没有任何一条边发生松弛，说明所有最短路已经收敛，可以直接 break。
  • 如何检测负环？ 做完 n − 1 轮后再多扫第 n 轮：如果还有边能松弛，说明存在一条边数 ≥ n 的路径比简单路径更短——根据抽屉原理，图里必有总权值 < 0 的环（负环）！

2. SPFA：只松弛“刚刚变短”的节点

Bellman-Ford 每轮盲扫所有 m 条边，时间复杂度固定 O(nm)。但仔细想一想：只有上一轮 dist[u] 真正变小的节点 u，才有可能把邻居拉得更短！

SPFA（Shortest Path Faster Algorithm）用一个普通队列 queue 和标记数组 inQueue[v]：

  • 每当 dist[v] 被松弛成功，如果 v 当前不在队列里，就把 v 入队等待它去更新邻居；
  • SPFA 判负环：维护 cnt[v] 记录起点到 v 的最短路经过的边数（松弛时 cnt[v] = cnt[u] + 1，或者统计节点入队次数）。一旦出现 cnt[v] ≥ n，立刻断定存在负环！
竞赛铁律：正权图千万别用 SPFA！
SPFA 在随机图上平均很快，但最坏复杂度仍是 O(nm)。NOI/洛谷等题库的正权最短路题通常会专门放“卡 SPFA”的网格图或菊花图数据（经典名言：“关于 SPFA，它死了”）。
选型口诀：边权全非负 → 堆优化 Dijkstra；有负权边或要判负环 → SPFA / Bellman-Ford。
算法时间复杂度支持负权边可判负环适用场景
堆优化 DijkstraO((n+m) log n)❌ 不支持❌ 不能非负权图首选（极稳）
Bellman-FordO(nm)✅ 支持✅ 第 n 轮点数边数较小 / 限边数最短路

实战题解：洛谷 P4779 与 P3385

掌握这两道洛谷经典模板题，就拿下了竞赛中最常用的两把最短路利器。下面代码均已优化 I/O，可直接提交 AC。

题目大意：给定一个 n 个点、m 条有向边的带非负权图（n ≤ 105，m ≤ 2 × 105），求从指定起点 s 出发到每个点的最短距离。

  • 为何选堆优化 Dijkstra？ 边权全部非负，且本题是著名的“卡 SPFA 模板题”，必须使用 O((n+m) log n) 的堆优化 Dijkstra。
  • 避坑要点：距离数组建议开 long long 防溢出；小根堆写法为 priority_queue<PLI, vector<PLI>, greater<PLI>>；弹出时务必写 if (d > dist[u]) continue;。
P4779_dijkstra.cpp (C++17 · 可直接提交) 
#include <bits/stdc++.h>
using namespace std;

using ll = long long;
using PLI = pair<ll, int>;
const ll INF = 4e18;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m, s;
    cin >> n >> m >> s;
    vector<vector<pair<int, int>>> g(n + 1);
    for (int i = 0; i < m; ++i) {
        int u, v, w;
        cin >> u >> v >> w;
        g[u].push_back({v, w});
    }

    vector<ll> dist(n + 1, INF);
    priority_queue<PLI, vector<PLI>, greater<PLI>> pq;
    dist[s] = 0;
    pq.push({0, s});

    while (!pq.empty()) {
        auto [d, u] = pq.top();
        pq.pop();
        if (d > dist[u]) continue; // 跳过堆中过期状态

        for (auto [v, w] : g[u]) {
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.push({dist[v], v});
            }
        }
    }

    for (int i = 1; i <= n; ++i) {
        cout << dist[i] << (i == n ? '\n' : ' ');
    }
    return 0;
}

题目大意：多组测试数据。给定 n 个点、m 条边（n ≤ 2000，m ≤ 3000），判断是否存在从节点 1 出发可以到达的负环，存在输出 YES，否则输出 NO。

  • 审题超级大坑！ 题目规定：若输入边权 w ≥ 0，则建双向边（u→v 与 v→u）；若 w < 0，则只建单向边（u→v）。
  • SPFA 判负环：只把起点 1 入队（确保只检测从 1 可达的负环），松弛时维护边数 cnt[v] = cnt[u] + 1，一旦 cnt[v] ≥ n 立刻返回 true。
P3385_spfa_neg_cycle.cpp (C++17 · 可直接提交) 
#include <bits/stdc++.h>
using namespace std;

const int INF = 0x3f3f3f3f;

void solve() {
    int n, m;
    cin >> n >> m;
    vector<vector<pair<int, int>>> g(n + 1);
    for (int i = 0; i < m; ++i) {
        int u, v, w;
        cin >> u >> v >> w;
        g[u].push_back({v, w});
        if (w >= 0) g[v].push_back({u, w}); // 注意题面：w >= 0 为无向边
    }

    vector<int> dist(n + 1, INF), cnt(n + 1, 0);
    vector<bool> inq(n + 1, false);
    queue<int> q;

    dist[1] = 0;
    q.push(1);
    inq[1] = true;

    while (!q.empty()) {
        int u = q.front();
        q.pop();
        inq[u] = false;

        for (auto [v, w] : g[u]) {
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                cnt[v] = cnt[u] + 1;
                if (cnt[v] >= n) { // 经过至少 n 条边 => 必有负环
                    cout << "YES\n";
                    return;
                }
                if (!inq[v]) {
                    q.push(v);
                    inq[v] = true;
                }
            }
        }
    }
    cout << "NO\n";
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T;
    cin >> T;
    while (T--) solve();
    return 0;
}
