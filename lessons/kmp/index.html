第 1 课 / 共 5 课动机与痛点

暴力匹配为什么慢？

给定一个长度为 n 的文本串 T 和长度为 m 的模式串 P，如何快速找出 P 在 T 中出现的所有位置？先看看最朴素的做法为什么会超时。

1. 朴素（暴力）匹配的做法

我们把模式串 P 对齐到文本串 T 的起点 s = 0，逐字符比较 T[s + j] 和 P[j]。一旦在某个位置发生失配，就把模式串往右挪 1 格（s + 1），然后让文本串指针 i 傻傻地回退到 s + 1，模式串指针 j 归零，一切推倒重来。

最坏情况：T = "aaaaaaab"，P = "aaaab" —— 每次都在最后一个字符失配，指针 i 反复回退

2. 最坏时间复杂度：O(n · m)

当 T = "aaaa...ab"（长度 n）、P = "aaa...ab"（长度 m）时，每个起始位置都要成功匹配前 m − 1 个 'a'，然后在最后一个 'b' 处功亏一篑。

竞赛里的致命后果：如果 n = 106，m = 5 × 105，暴力匹配最多需要约 2.5 × 1011 次比较，在 1 秒时限（约 108 次运算）下直接 TLE（超时）！

第 2 课 / 共 5 课核心顿悟

永不回退的 i 与“真前后缀（Border）”

KMP 算法（Knuth–Morris–Pratt）的惊人之处在于：文本串指针 i 从头走到尾，永远不会往回退哪怕一步！凭什么？

1. 失配的那一刻，其实我们掌握了“上帝视角”

假设在 T[i] ≠ P[j] 处失配了。虽然这一格没对上，但前面的 j 个字符已经全部匹配成功！也就是说，文本串里紧挨在 T[i] 左边的那段子串，和模式串的前缀 P[0..j-1] 是一模一样的。

既然已经知道 T[i-j .. i-1] 长什么样，我们根本不用回头重看文本串！只要把模式串 P 往右滑动，滑到模式串开头的一段（真前缀）刚好能和已匹配部分的结尾（真后缀）重合为止！

2. 什么是“真前后缀”与 Border？

  • 真前缀（Proper Prefix）：从开头截取、但不能等于整个字符串本身的前缀。例如 "ababa" 的真前缀有 "a"、"ab"、"aba"、"abab"。
  • 真后缀（Proper Suffix）：从结尾截取、但不能等于整个字符串本身的后缀。例如 "ababa" 的真后缀有 "a"、"ba"、"aba"、"baba"。
  • Border（公共真前后缀）：既是真前缀、又是真后缀的子串。例如 "ababa" 的 Border 有 "a"（长度 1）和 "aba"（长度 3），其中最长 Border 长度为 3。
在 j = 5 失配时，已匹配串 "ababa" 的最长 Border 是 "aba"（长度 3），因此直接令 j = 3，i = 5 纹丝不动！
一句话记住 KMP 跳转规律：当 T[i] ≠ P[j] 时，我们把 j 改成“已匹配前缀 P[0..j-1] 的最长 Border 长度”，然后继续拿新的 P[j] 去和同一个 T[i] 比较！

第 3 课 / 共 5 课核心难点拆解

前缀函数 π[i]（即 next 数组）与 O(m) 递推

既然失配时每次都要查“P[0..j-1] 的最长 Border 长度”，我们只要提前对模式串 P 算好这张表，就能 O(1) 查表跳转！

1. 前缀函数 π[i] 的定义

π[i] = 子串 P[0..i] 的最长相等真前后缀（Border）的长度

特别地，单个字符没有真前后缀，所以恒有 π[0] = 0。以 P = "ababaca" 为例：

下标 i0123456
字符 P[i]ababaca
前缀 P[0..i]aababaababababaababacababaca
最长 Border——aababa—a
π[i]0012301
关于名字：教材/OI-Wiki 常用 0-indexed 的前缀函数 π[i]（或 pi[i]）；竞赛中常称它为 next[i]（或 1-indexed 的 nxt[i]），本质完全一样，都是“最长 Border 长度”。

2. 通俗拆解最让人头晕的那一行代码

求 π[i] 时，假设我们已经算出了 j = π[i - 1]（即 P[0..i-1] 的最长 Border 长度）。现在新来了一个字符 P[i]：

  • 顺风局：如果 P[i] == P[j]，太棒了！直接把原来的 Border 延长 1 格，π[i] = j + 1。
  • 逆风局：如果 P[i] ≠ P[j]，我们只好退而求其次，找 P[0..i-1] 的次长 Border，看看它的下一个字符能不能和 P[i] 配上。怎么找次长 Border？
while (j > 0 && p[i] != p[j]) j = pi[j - 1];
核心直觉：次长 Border 就是“最长 Border 的 Border”！
因为当前长度为 j 的前缀 A = P[0..j-1] 和末尾长度为 j 的后缀 B 完全相等。所以任何更短的公共前后缀，既是 A 的前缀，也是 B（也就是 A）的后缀——换句话说，它一定是 P[0..j-1] 自己的 Border！而 P[0..j-1] 的最长 Border 长度，早就存在 π[j - 1] 里了！
把 j 跳到 π[j-1]，就会从长到短不重不漏地试遍所有可能的 Border

第 4 课 / 共 5 课完整流程与均摊分析

完整 KMP 匹配与为什么复杂度是 O(n + m)

学会了求 π[]，KMP 的匹配阶段几乎就是复制粘贴同一段代码！但很多初学者看到 for 里面套着 while，会怀疑它是不是 O(n·m)？

1. 完整匹配与“重叠匹配”的小技巧

我们用 j 表示当前已经匹配了 P 的前 j 个字符。从 i = 0 遍历到 n - 1：

  1. 如果失配（T[i] ≠ P[j]），就不断执行 j = pi[j - 1]，直到能配上或 j == 0。
  2. 如果 T[i] == P[j]，就令 j++。
  3. 命中判定：如果 j == m，说明在起始下标 i - m + 1 找到了一次完整匹配！记录答案后，立刻执行 j = pi[j - 1]——假装下一位“失配”了，把模式串滑到最长 Border 对齐处，这样就不会漏掉像 "aba" 在 "ababa" 中出现 2 次这样的重叠匹配！

2. 为什么 for 套 while 居然是 O(n + m)？

用“存钱罐（势能）”直觉一秒看穿：

  • 把 j 的值想象成存钱罐里的硬币数，初始为 0，且永远不会变成负数（j ≥ 0）。
  • 外层 for 循环一共跑 n 轮，每轮里 j++ 最多只执行 1 次——也就是整个过程最多往里存 n 枚硬币。
  • 内层 while 每跳一次 j = pi[j - 1]，因为真前后缀严格短于原串（pi[j - 1] < j），j 至少减少 1（至少花掉 1 枚硬币）。
  • 你花掉的硬币绝不可能超过存进去的硬币！因此，无论 while 在某一轮突然连跳多少次，它在整个算法运行期间的总执行次数绝不超过 n 次！
总时间复杂度 = 构造 π[] 的 O(m) + 匹配扫描的 O(n) = O(n + m)

第 5 课 / 共 5 课竞赛实战与高频结论

实战题解：洛谷 P3375 模板与最小循环节

掌握这两道必刷题，你就彻底打通了 KMP 在竞赛与面试中的两大核心考法：线性多处匹配与Border 循环节性质。

洛谷 P3375 题目大意：给出两个字符串 s1（文本串）和 s2（模式串），长度均 ≤ 106。第一部分按从小到大输出 s2 在 s1 中每次出现的1-indexed 起始位置；最后一行输出 s2 每个前缀的最长 Border 长度（即 π[0..m-1]）。

建模要点：用 0-indexed 写出最干净的 π[] 与匹配循环。当 j == m 时，0-indexed 起点是 i - m + 1，转成题目要求的 1-indexed 只需再加 1，即 i - m + 2。别忘了命中后令 j = pi[j - 1]！
🧪 一键演练 P3375 官方样例
载入 s1="ABABABC"、s2="ABA"，核对输出位置 1, 3 与 Border 数组 0 0 1！
C++17 · 洛谷 P3375 可直接 AC 代码 
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string s1, s2;
    cin >> s1 >> s2;
    int n = (int)s1.size(), m = (int)s2.size();

    // 1. O(m) 计算 s2 的前缀函数 pi[]（即 Border 长度数组）
    vector<int> pi(m, 0);
    for (int i = 1, j = 0; i < m; ++i) {
        while (j > 0 && s2[i] != s2[j]) j = pi[j - 1];
        if (s2[i] == s2[j]) ++j;
        pi[i] = j;
    }

    // 2. O(n) KMP 匹配，输出所有 1-indexed 起始位置
    for (int i = 0, j = 0; i < n; ++i) {
        while (j > 0 && s1[i] != s2[j]) j = pi[j - 1];
        if (s1[i] == s2[j]) ++j;
        if (j == m) {
            cout << (i - m + 2) << '\n'; // 0-indexed 是 i-m+1
            j = pi[j - 1];               // 继续寻找重叠匹配
        }
    }

    // 3. 输出 Border 数组
    for (int i = 0; i < m; ++i) {
        cout << pi[i] << (i + 1 == m ? '\n' : ' ');
    }
    return 0;
}

高频结论 · 洛谷 P4391 / POJ 2406 题目大意：给定一个长度为 n 的字符串 S，求它的最小循环节长度（即最短的子串长度 L，使得 S 是由长度为 L 的子串不断重复拼接后截取的前缀）。

最小循环节长度 L = n − π[n − 1]

为什么成立？令 L = n − π[n - 1]。因为长度 π[n - 1] 的前缀和后缀完全相等，也就是对任意下标 k（0 ≤ k < n − L）都有 S[k] == S[k + L]！这意味着整个字符串每隔 L 个字符就完全重复一次，所以 L 一定是循环节；又因为 π[n - 1] 是最大的 Border，所以 n − π[n - 1] 就是最小循环节！

两种常见变体别搞混：
1. 允许末尾不完整循环（如 "abcabcab"，洛谷 P4391）：答案恒为 n - pi[n - 1]（此处 8 − 5 = 3，循环节 "abc"）。
2. 要求严格整数次重复（如 POJ 2406 / LeetCode 459）：需额外判断 n % L == 0 且 pi[n - 1] > 0；若不整除则只能整体算 1 次循环。
🧪 演示循环节字符串 "abcabcab" 的 π 数组
在右侧构建 P="abcabcab" 的 π[]，直观验证 n = 8, π[7] = 5 ⇒ L = 8 - 5 = 3！
C++17 · 洛谷 P4391 最小循环节 AC 代码 
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    string s;
    cin >> n >> s;

    vector<int> pi(n, 0);
    for (int i = 1, j = 0; i < n; ++i) {
        while (j > 0 && s[i] != s[j]) j = pi[j - 1];
        if (s[i] == s[j]) ++j;
        pi[i] = j;
    }

    int L = n - pi[n - 1];
    cout << L << '\n';
    // 若题目要求严格整数次重复（如 LeetCode 459）：
    // bool exact = (pi[n - 1] > 0 && n % L == 0);
    return 0;
}
