第 1 课 · 动机与直觉 约 3 分钟

为什么我们需要“搜索树”？

在写代码时，我们经常要维护一个动态变化、又需要随时快速查找的数字集合。数组和链表各自卡在了一个死胡同里。

1. 数组与链表的两难困境

数据结构查找一个数插入 / 删除一个数痛点
有序数组O(log n) 二分查找O(n) 后面全部挪位改数据太慢
有序链表O(n) 从头挨个找O(1) 改指针（找到位置后）找数据太慢
平衡搜索树O(log n)O(log n)鱼与熊掌兼得！

2. 核心灵感：把“二分查找”画成一棵树

回想一下你在有序数组 [10, 15, 22, 30, 40, 50, 65] 中二分查找数字 22 的过程：

  1. 先看正中间的 30：发现 22 < 30，于是直接扔掉右半边！
  2. 再看左半边中间的 15：发现 22 > 15，于是往右走！
  3. 刚好撞见 22，查找成功！

如果我们把“正中间的数”拎起来当树根，把左半边挂在左边、右半边挂在右边，就得到了一棵二叉搜索树（Binary Search Tree，简称 BST）！

BST 的唯一铁律（记住这一句话就懂了一半）：
对于树中的任意一个节点：
• 它左子树里所有节点的值，都严格 小于 它；
• 它右子树里所有节点的值，都严格 大于 它。
🧪 微实验 1：亲眼看一次“砍半查找”
右侧已经为你建好了一棵 7 节点的搜索树。点击按钮，观察查找 22 和查找 45（不存在）时路径是如何一步步缩小的。

3. 一个超有用的副产品：中序遍历天然有序

因为永远满足“左 < 根 < 右”，只要按照 左子树 → 根 → 右子树 的顺序（即中序遍历）把整棵树读一遍，得到的必然是从小到大排好序的序列！你可以观察右下角的“中序遍历序列”条，无论怎么增删，它永远有序。

第 2 课 · 核心操作 约 5 分钟

BST 如何插入、找前驱后继，以及最难的“删除”？

查找和插入非常符合直觉，真正的难点在于：如果要删掉一个“左右都有孩子”的节点，剩下的子树怎么办？

1. 插入：沿着查找路线走到空位

插入一个新数 x 和查找一模一样：从根出发，比当前节点小就往左，大就往右，直到走到一个空指针 nullptr，直接把新节点挂在这里就行。新节点刚插入时一定是叶子。

🧪 微实验 2：插入一个新节点
观察数值 26 如何一路比较 30 → 15 → 22，最后落脚在 22 的右下方。

2. 前驱与后继：最接近它的“左右邻居”

  • 前驱（Predecessor）：树中严格小于 x 的最大数（排在 x 前面紧挨着的数）。
  • 后继（Successor）：树中严格大于 x 的最小数（排在 x 后面紧挨着的数）。

找前驱的口诀：从根往下走，只要遇到 u.key < x，就记下来当“候选答案”并往右走试图找更大的；否则太大了，只能往左走。

3. 难点攻克：删除节点的三种情况

假设我们已经找到了要删的节点 u：

  • 情况 A（叶子节点，0 个孩子）：最简单，直接拔掉。
  • 情况 B（只有 1 个孩子）：让唯一的孩子直接“子承父业”，顶替 u 的位置。
  • 情况 C（左右都有孩子，2 个孩子）：不能直接拆掉，否则一棵树会裂成两半！怎么办？找替身！
“找替身”的绝妙思路：
谁最有资格替代 u 坐在王位上，既比整个左子树大，又比右子树剩下的所有人都小？
答案正是 u 的后继（右子树中一路向左找到的最小节点）！
因为它是右子树里最小的，所以它一定没有左孩子！把它抄到 u 的位置后，再去删掉原来的那个替身节点——这就瞬间转化成了简单的情况 A 或情况 B！

第 3 课 · 转折点 约 3 分钟

灾难降临：当 BST 退化成一根“糖葫芦”

普通 BST 在随机数据下很快，但一旦遇到有序数据，它的性能会瞬间崩盘。

1. 亲手制造一场性能灾难

假设用户按时间顺序依次往普通 BST 里插入：10, 20, 30, 40, 50, 60。

每来一个新数，都比前面所有的数大，于是它只能不断往右下方挂……最后整棵树变成了一根长长的斜链！

🧪 微实验 4：同组数据，天壤之别！
先点左边按钮，看普通 BST 怎么长成 6 层的斜链；再点右边按钮，看 AVL 平衡树如何自动施展“旋转魔法”，把树高压死在 3 层！

2. 树高决定命运

在搜索树中，查找、插入、删除的最坏耗时都直接等于树高 h：

  • 退化成链时：n = 100,000 个节点，树高 h = 100,000，查一次要做 10 万次比较，彻底沦为链表（O(n)）！
  • 保持平衡时：n = 100,000 个节点，树高 h ≈ 17，查一次最多只需 17 次比较（O(log n)）！
引入平衡树的核心思想：
既然“长歪”是罪魁祸首，那我们就在每次插入或删除之后，顺手检查一下树有没有长歪——只要发现哪边太沉，就立刻做一次局部结构调整（旋转），把树重新扶正！

第 4 课 · 核心机制 约 6 分钟

AVL 树：平衡因子与“旋转”的真正本质

很多人觉得旋转很玄学，其实它只有两件事：守住中序有序 + 把夹在中间的子树过继给旧根。

1. 怎么量化“有没有长歪”？——平衡因子 BF

AVL 树给每个节点记录一个子树高度 h（空节点高度为 0，叶子高度为 1），并定义平衡因子（Balance Factor）：

BF(u) = h(u 的左子树) − h(u 的右子树)
  • 如果 BF ∈ {-1, 0, +1}：左右身高差不超过 1，健康平衡！
  • 如果 |BF| = 2：左边比右边高了 2 层（+2）或右边高了 2 层（-2），警报拉响，必须旋转！

数学上可以证明：只要每个节点都守住 |BF| ≤ 1，树高严格满足 h < 1.44 log2(n + 2)，彻底告别退化！

2. 旋转的本质：右旋与“子树过继”（必懂！）

看下面这张图，假设旧根 y 的左子树太高了，我们要把它的左孩子 x 提拔成新根（右旋）：

旋转前后中序遍历完全不变：永远是 T1 < x < T2 < y < T3！

只看三行代码就能写完右旋：

  1. x 当新根，旧根 y 顺理成章成为 x 的右孩子；
  2. 可是 x 原本的右孩子 T2 被挤出来了，去哪？因为 x < T2 < y，它正好挂在 y 空出来的左孩子位置上！
  3. 最后依次更新 y 和 x 的高度即可（先子后父）。左旋就是把上面左右完全镜像过来！

第 5 课 · 失衡分类 约 5 分钟

LL、RR、LR、RL：四大失衡一眼识别！

从失衡节点往下数两步，沿着“更高的那一侧”走，路径只可能有 4 种形状。

1. 为什么折线型（LR / RL）不能直接单旋？

想象 30 → 左孩子 10 → 右孩子 20（这是一条“之”字形折线，即 LR 型）。如果你强行对 30 直接右旋，20 会被过继给 30 当左孩子，树变成 10 → 右孩子 30 → 左孩子 20——只是换了个方向继续弯折，树高还是 3，根本没平衡！

万能口诀（背下这 16 个字终身不忘）：
同向失衡直接单旋（LL 右旋、RR 左旋）；
折线失衡先掰直再单旋（LR 先左后右、RL 先右后左）。

2. 四大场景对照与实时演练

LL 型（左左）单次右旋

条件：bf(u)=+2 且 bf(u.L) ≥ 0。一路向左歪，对 u 右旋一次搞定。

RR 型（右右）单次左旋

条件：bf(u)=-2 且 bf(u.R) ≤ 0。一路向右歪，对 u 左旋一次搞定。

LR 型（左右）先左旋再右旋

条件：bf(u)=+2 且 bf(u.L) < 0。先对左孩子左旋掰成 LL，再对 u 右旋。

RL 型（右左）先右旋再左旋

条件：bf(u)=-2 且 bf(u.R) > 0。先对右孩子右旋掰成 RR，再对 u 左旋。

3. 拓展视野：除了 AVL，竞赛和工程还用哪些平衡树？

平衡树特点与优势何时选用
AVL 树最严格平衡，查询最快理解平衡树原理的最佳起点；读多写少场景
红黑树放宽平衡条件，旋转次数少C++ std::set/map、Java TreeMap 底层实现
FHQ-Treap无旋，仅靠 split/merge (~40行)OI / ACM 竞赛最推荐手写！支持查排名/第 k 小/区间翻转
Splay 树访问谁就把谁旋到根LCT 动态树、文艺平衡树区间操作

第 6 课 · 学以致用 从入门到模板

给平衡树装上“名次外挂” + 三道经典题解

学会原理后，怎么在算法题里真正用起来？记住一条实战黄金法则：只需前驱后继用 std::set，需要查排名/第 k 小才手写平衡树！

给节点加一个字段 sz，解锁“第 k 小”与“查排名”

只需让每个节点顺便记录以自己为根的子树共有多少个节点（sz = 1 + sz(L) + sz(R)），查询第 k 小瞬间变得像二分一样简单：

  • 看左子树人数 ls = sz(u.left)：
  • 若 k ≤ ls，第 k 小一定在左子树；
  • 若 k == ls + 1，当前节点 u 就是答案！
  • 若 k > ls + 1，减去左边和自己（k -= ls + 1），去右子树找！

精选三道梯度实战题（由浅入深）

题意：给定连续 n 天的营业额，每天要从“之前所有天”里找一个与当天最接近的数，累加最小差值。

思路：与当天营业额 x 最接近的历史数值，一定是 x 的前驱或后继！不需要查第 k 小，直接用 C++ 内置红黑树 std::set + 左右哨兵（-INF, +INF）即可 15 行 AC！

Luogu_P2234_set.cpp（O(n log n)） 
#include <bits/stdc++.h>
using namespace std;
const long long INF = 1e15;

int main() {
    ios::sync_with_stdio(false); cin.tie(nullptr);
    int n; cin >> n;
    set<long long> s = {-INF, INF}; // 哨兵免去边界特判
    long long ans = 0;
    for (int i = 1; i <= n; i++) {
        long long x; cin >> x;
        if (i == 1) ans += x;
        else {
            auto it = s.lower_bound(x); // 第一个 >= x（自身或后继）
            auto pre = prev(it);        // 严格 < x 的最大数（前驱）
            ans += min(*it - x, x - *pre);
        }
        s.insert(x);
    }
    cout << ans << '\n';
}

题意：大小为 k 的窗口在数组上向右滑动，求每个窗口内的中位数。

思路：用可重平衡树 std::multiset 维护窗口，并用一个迭代器 mid 始终指着中位数。每次滑入一个数、滑出一个数时，根据新旧元素与 *mid 的大小关系微调 --mid 或 ++mid，单步严格 O(log k)！

LeetCode_480_multiset.cpp（O(n log k)） 
class Solution {
public:
    vector<double> medianSlidingWindow(vector<int>& nums, int k) {
        multiset<int> win(nums.begin(), nums.begin() + k);
        auto mid = next(win.begin(), k / 2);
        vector<double> res;
        for (int i = k; ; i++) {
            double m = (k & 1) ? (double)(*mid)
                               : ((double)(*mid) + *prev(mid)) / 2.0;
            res.push_back(m);
            if (i == (int)nums.size()) break;
            win.insert(nums[i]);
            if (nums[i] < *mid) --mid;
            if (nums[i - k] <= *mid) ++mid;
            win.erase(win.lower_bound(nums[i - k])); // 只删一个
        }
        return res;
    }
};

题意：维护可重集合，支持 6 大操作：插入、删一个、查排名、查第 k 小、查前驱、查后继。

思路：因为 std::set 查不了第 k 小，竞赛中最常用 FHQ-Treap（无旋平衡树）：只用 split（按值劈成两棵树）和 merge（按随机堆优先级合起来），完全不用写四种旋转，代码不到 60 行就能稳定 AC！

Luogu_P3369_FHQ_Treap.cpp（完整可交） 
#include <bits/stdc++.h>
using namespace std;
const int MAXN = 100005;
mt19937 rng(114514);

struct Node { int l, r, val, sz; unsigned int pri; } tr[MAXN];
int root = 0, idx = 0;

int newNode(int v) { tr[++idx] = {0, 0, v, 1, rng()}; return idx; }
void pushUp(int u) { tr[u].sz = tr[tr[u].l].sz + tr[tr[u].r].sz + 1; }

void split(int u, int v, int &x, int &y) {
    if (!u) { x = y = 0; return; }
    if (tr[u].val <= v) x = u, split(tr[u].r, v, tr[u].r, y);
    else                y = u, split(tr[u].l, v, x, tr[u].l);
    pushUp(u);
}

int merge(int x, int y) {
    if (!x || !y) return x | y;
    if (tr[x].pri < tr[y].pri) { tr[x].r = merge(tr[x].r, y); pushUp(x); return x; }
    else                       { tr[y].l = merge(x, tr[y].l); pushUp(y); return y; }
}

int kth(int u, int k) {
    while (true) {
        int ls = tr[tr[u].l].sz;
        if (k <= ls) u = tr[u].l;
        else if (k == ls + 1) return tr[u].val;
        else k -= ls + 1, u = tr[u].r;
    }
}

int main() {
    ios::sync_with_stdio(false); cin.tie(nullptr);
    int n, opt, x, a, b, c; cin >> n;
    while (n--) {
        cin >> opt >> x;
        if (opt == 1) { split(root, x, a, b); root = merge(merge(a, newNode(x)), b); }
        else if (opt == 2) {
            split(root, x, a, c); split(a, x - 1, a, b);
            b = merge(tr[b].l, tr[b].r); // 只删一个 x
            root = merge(merge(a, b), c);
        } else if (opt == 3) {
            split(root, x - 1, a, b); cout << tr[a].sz + 1 << '\n'; root = merge(a, b);
        } else if (opt == 4) {
            cout << kth(root, x) << '\n';
        } else if (opt == 5) {
            split(root, x - 1, a, b); cout << kth(a, tr[a].sz) << '\n'; root = merge(a, b);
        } else {
            split(root, x, a, b); cout << kth(b, 1) << '\n'; root = merge(a, b);
        }
    }
}
